# 요구사항 및 화면·상태 정의

## 범위와 우선순위

- R01/P0: 서버에서 인증, 역할 권한, mart 범위를 매 조회·수정·작업·다운로드에 강제한다.
- R02/P1: 상품 검색/필터/정렬/상세 수정, 문자열 바코드, 안전한 가격 타입, optimistic locking, 변경 감사.
- R03/P1: 일괄 변경과 엑셀은 검증→미리보기→명시적 확정→비동기 반영→행별 결과. 재실행 중복을 방지한다.
- R04/P0: 이미지 업로드·검증·처리·서빙 분리. 새 버전 READY와 활성화 성공 전까지 기존 정상 이미지 유지.
- R05/P0: 문자 접수와 Outbox 원자 저장. 발송사 접수/실제 전달/UNKNOWN 구분, 중복·역순 이벤트·대사 지원.
- R06/P0: 감사·알림·백업·복구·배포 원복. 유료 서비스 실호출은 명시적으로 활성화하고 검증한 뒤 수행한다.
- R07/P1: 확인된 레거시 기능 호환. 미확인 기능은 검증 전 신규 업무 규칙을 만들지 않는다.

## 권한 초안

| 주체 | 범위 | 허용 후보 |
|---|---|---|
| 시스템 관리자 | 명시적으로 허용된 전체 또는 선택 마트 | 관리자·마트 권한 관리, 운영 설정 |
| 마트 운영자 | 배정된 마트 | 상품·이미지·확인된 재고·엑셀 |
| 메시지 담당자 | 배정 마트+발송 권한 | 캠페인 등록/중단, 마스킹된 결과 |
| 감사 조회자 | 허용 범위 읽기 | 감사·작업·시스템 현황 |

역할명은 PRD 목표다. 실제 레거시 역할과 역할 조합은 U04에서 확인한다. 별도 권한 예: `product.read/write`, `job.confirm`, `message.send`, `message.reconcile`, `audit.read`, `pii.read`. 권한 이름과 조합은 제안이다. martId를 받더라도 사용자에게 허용된 범위와 교집합을 적용한다. 타 마트 객체 ID는 404로 통일하는 초안이며 감사에는 접근 거부를 남긴다.

## UI 상태와 동작

상품 목록은 검색·필터 툴바와 선택 작업 바를 분리한다. 검색조건은 URL로 보존하되 전화번호 등 PII는 URL에 넣지 않는다. 서버 페이지네이션/정렬, 고정 주요 열과 열 설정, 키보드 탐색을 제공한다. 단가·품절 등 종속 규칙 확인 전 인라인 편집 허용 목록을 확정하지 않는다.

모든 화면에 로딩/빈 결과/권한 부족/네트워크 오류/재시도 상태가 필요하다. 수정 충돌은 최신 값과 내 변경값을 비교하고 재검토하게 한다. 통신 실패를 저장 실패로 단정하지 않고 같은 멱등 키로 결과를 조회한다. 이미지 실패는 기존 이미지와 오류 배지를 함께 표시한다.

| 대상 | 상태 초안 | UX 규칙 |
|---|---|---|
| 이미지 | UPLOAD_PENDING, UPLOADED, PROCESSING, READY, FAILED, EXPIRED | READY와 대표 활성화 구분. 실패 시 원인/재처리 |
| 대량 작업 | VALIDATING, AWAITING_CONFIRMATION, QUEUED, RUNNING, SUCCEEDED, PARTIALLY_FAILED, FAILED, CANCEL_REQUESTED, CANCELLED, EXPIRED | 검증 실패는 FAILED+행 오류. 중단은 이미 커밋된 행을 되돌리지 않음 |
| 문자 | PENDING, QUEUED, PROCESSING, ACCEPTED_BY_PROVIDER, DELIVERED, FAILED, UNKNOWN, CANCELLED, EXPIRED | ACCEPTED를 전달 성공으로 표시하지 않음 |
| 예약 캠페인 | SCHEDULED, RUNNING, CANCEL_REQUESTED, COMPLETED, CANCELLED | 집계와 메시지별 실제 상태 별도. UNKNOWN 건수 표시 |

상품의 노출/품절/인기 플래그는 독립 후보다. PNG의 Published/Draft/Archived에 일괄 대응시키지 않는다. 취소는 아직 외부 전송을 시작하지 않은 메시지에만 확정할 수 있다. 예약은 KST 입력을 UTC 절대시각으로 변환해 표시하고 dispatch 직전 동의·차단·예약시각을 다시 검증한다.

## 비기능 목표와 결정 대기

PRD 후보인 월 가용성 99.9%, 상품검색 p95 500ms, 내부 큐→발송사 접수 p95 60초, RTO 1시간/RPO 15분은 **미검증 목표**다. 데이터량·검색조건·정상 발송량·제외 시간·측정 구간·비용 합의 전 성능 보증이나 인수 수치로 확정하지 않는다. Phase 1에서 부하 프로파일을 합의하고 Phase 5에서 실측한다.

인증은 동일 출처 BFF 없이 Spring 세션+HttpOnly/Secure 쿠키를 우선 검토한다. 실제 SSO 여부는 미확인이다. 쿠키 인증에는 CSRF 방어, 출처 제한과 세션 만료 정책이 필요하다. PII는 저장·전송·로그·결과 파일 별로 접근통제/암호화/보존을 정의한다. 광고 발송의 법적 허용 시간과 동의 요건은 운영·법무 확인 대상이며 이 문서는 법률 판정이 아니다.
