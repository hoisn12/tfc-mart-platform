상위 경로의 AGENTS.md도 읽기 확인했으며 발견하지 못했다. 운영 시스템, 외부 저장소, 운영 DB 및 발송사에는 접근하지 않았다. 폴더 밖 다른 프로젝트를 이 시스템의 레거시로 간주하지 않았다.

## 현재 구조 평가

분석 가능한 기존 애플리케이션 구조가 없다. React/Java 도입 상태, 레이어 의존성, 기존 API 보존 대상, 쿼리 병목, 배포 방식, 취약점과 테스트 커버리지는 **미확인**이다. 코드가 없다는 사실을 운영 시스템이 없다는 뜻으로 해석하지 않는다. 기반 명세가 요구하는 신규 구조를 설계하되 기존 시스템 호환성은 자료 확보 후 검증한다.

PRD가 언급하는 한글 ‘상품관리(마트)’ 레거시 스크린샷은 현재 제공 파일에서 확인되지 않았다. `example.png`는 신규 UX 참고 자료로 분류한다. 영문 화면의 Draft/Archived 상태, 매출 KPI, 판매채널 메뉴를 레거시 기능 또는 신규 필수 업무로 채택하지 않는다. PNG 내 수치와 가격 예시는 테스트 목표나 실제 데이터가 아니다.

## 레거시 잠정 분석

PRD §1의 메뉴·필드는 기능 후보의 근거로 활용할 수 있으나 동작, 권한, 삭제 규칙, 데이터 정합성의 근거는 아니다. 특히 재고 수치와 품절 플래그의 관계, 단가/세일가 우선순위, 무배제외의 계산 범위, 묶음 주문 규칙은 확정할 수 없다.

기존 이미지 장애 원인과 문자 유실·중복 발생 여부도 실제 장애 로그가 없어 미확인이다. Outbox 및 이미지 CDN 설계는 요구되는 예방 구조이며 현재 장애 원인 진단 결과가 아니다.

## 우선 확보할 자료

1. 비식별 레거시 소스/DDL/마이그레이션/API 계약과 읽기 전용 테스트 환경.
2. 운영자와 함께 수행하는 메뉴별 화면 녹화·정상/예외 시나리오·역할별 접근 기록.
3. 비식별 엑셀 샘플, 바코드/가격/재고 경계 사례, 외부 연계 목록.
4. 이미지 저장 경로·권리·누락 목록, 발송사 계약 기능·익명화된 요청/결과/장애 로그.
5. 마트/상품/동시 사용자/업로드/발송량, 비용·RTO/RPO·운영 담당자 합의.

자료 확보 뒤 기능 매트릭스의 상태와 ERD/API를 수정하고 보존할 기존 인터페이스를 확정한다. 현재 단계에서는 데이터 이전량·일정·클라우드 비용을 산출할 근거가 없다.
