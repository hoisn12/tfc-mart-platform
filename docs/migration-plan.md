Phase 1부터 Outbox 저장 경계와 감시 계약을 준비하고 문자 흐름은 Phase 4에서 완성한다. 문자 우선순위를 앞당기려면 Foundation 이후 의존조건을 충족하도록 순서를 재검토한다. 미확인 주문 등 업무가 크면 Phase 5를 검증 가능한 단위로 재계획하며 빈 스텁을 완료로 보지 않는다.

## 이관·병행 검증

1. DDL·외부 의존·데이터 책임자 확정. 구/신ID·시각·금액·바코드·이미지·동의 매핑과 거부행 처리 기록.
2. 비식별 사본으로 이관 리허설. 건수·참조·중복·금액 집계·이미지 체크섬/도달성·동의를 대사하고 누락값을 임의 보완하지 않음.
3. shadow는 읽기 비교만 허용. 문자/결제/알림 부수효과 차단. 구URL과 신규 이미지 매핑 보존.
4. 변경 반영 방식은 CDC 가능 여부와 중단 허용으로 결정. CDC 불가 시 쓰기 정지→최종 차분→대사→라우팅 전환. 근거 없는 dual write 금지.
5. 마트/기능별 쓰기 주체를 플래그/라우팅으로 하나로 고정. 오래된 큐 작업·스케줄러까지 포함.
6. 소범위 전환 후 오류/큐/UNKNOWN/이미지403·404/업무 차이를 합의 기간 감시하고 임계 초과 시 확대 중단.

## 원복 조건

expand/contract로 이전 앱 호환성을 유지한다. 신규 쓰기 후 구시스템으로 돌아가려면 역매핑·차분 재반영·대사·쓰기 재고정이 필요하다. 역변환 불가 시 옛 DB 스냅샷으로 단순 복귀하지 않고 신규 환경에서 복구한다.

문자는 이미 발생한 외부 부수효과를 되돌릴 수 없다. 양쪽 발송대장·발송사ID·UNKNOWN을 연속 관리하고 Outbox/DLQ 재처리가 재발송을 만들지 않도록 한다. 이미지는 구버전을 보관해 포인터 복귀를 지원하며 긴급 삭제는 CDN TTL/purge 절차를 포함한다.
